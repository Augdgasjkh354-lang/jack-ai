# 开发版架构优化

Jack 2026-11-21 定的：只做风险小或没风险的，风险大的先不动。正式版暂停开发，只管开发版。

现状：一个模块，约 7.7 万行 Kotlin（`com.jack.ai` 6.6 万 + 内置的 mika 1.1 万）。`data/` 121 个文件、2.2 万行，什么都往里放；`ui/` 88 个文件、2.3 万行。最大的几个文件：浏览器 `JackBrowser.kt` 2554 行、`BrowserActivity.kt` 2191 行，`ChatViewModel.kt` 1448 行。

## 判断风险的规矩

- **没风险**：整块挪代码（一个函数、一个类原样搬到新文件，同一个包）。编译器能查出所有引用问题，逻辑一个字不改。挪完用脚本核对：挪前挪后的代码行一模一样（除了 import 和 `private` → `internal`）。
- **风险小**：改包名、把对象里的函数挪成扩展函数。编译器也能全查出来，但改动面大。
- **先不动**：改数据怎么存、改线程和状态怎么流、拆成多个 Gradle 模块、换框架。
- **永远别挪的**：
  - WorkManager 的 Worker 类：`Updater`、`Proactive`、`WeChat`、`Timeline`、`Routines`、`GoalWorker`、`Dreamer` 这几个文件里的。手机上排好的任务按类的全名存着，挪了包名会找不到。
  - `AndroidManifest.xml` 里登记的 Activity、Service、Receiver、桌面小组件。
  - 存进文件的 `@Serializable` 类的字段名（包名可以改，这个项目没用多态序列化，存的 JSON 里没有类名）。

## 第 1 批（已做）

- CI 不再打包、编译正式版，打包快一些，正式版的问题也不会挡住开发版发版。正式版代码先留着。
- 拆大文件，全是整块挪动：
  - `ChatScreen.kt` 1225 → 620：输入栏搬到 `ChatInput.kt`，空白页搬到 `ChatEmptyState.kt`。
  - `Messages.kt` 1150 → 472：图片、文件卡片搬到 `MessageFiles.kt`；思考进度、清单、工具时间线、交付清单搬到 `MessageWork.kt`。
  - `DesignEditor.kt` 1294 → 910：底部面板和弹层搬到 `DesignEditorPanels.kt`。
  - `Skills.kt` 1145 → 128：内置技能搬到 `BuiltinSkills.kt`，工具定义搬到 `SkillTools.kt`。
  - `ChatViewModel.kt`：`UiState` 搬到 `UiState.kt`；`BrowserTools.kt`：`BrowserDiff` 单独一个文件。
- 编译配置：开 Gradle 编译缓存，给 Kotlin 编译守护进程 3G 内存（之前在云端容器里会内存不够崩掉，重编一遍要十几分钟）。

## 第 2 批（已做）

1. **`data/` 按领域分了子包**（121 个文件 → 根上 61 个 + 7 个子包），每个领域单独一次提交，只改包名、import 和全名引用：
   - `data/design/`：设计模板、风格、字体、成组、元素库、花字、图表
   - `data/office/`：Word、Excel、PPT、PDF 和它们的图表、表格
   - `data/media/`：视频剪辑、音频、节拍、音效、字幕、配音、二维码
   - `data/memory/`：对话记忆、记忆整理和回看、深处回忆、事实库、前情提要、压缩
   - `data/browser/`：下载记录、流程、浏览记录、统计、网站笔记
   - `data/integrations/`：GitHub、Notion、邮箱、MCP、12306、远程配对
   - `data/phone/`：手机数据和文件、使用统计、Linux 沙箱、跑代码
   - 7 个 Worker 所在的文件按规矩没动。
2. **浏览器两个大文件拆开了**：`JackBrowser.kt` 2554 → 1235 行（拆出 `JackBrowserPageOps`、`JackBrowserTabs`、`JackBrowserDownloads`、`JackBrowserExtras`）；`BrowserActivity.kt` 2191 → 1028 行（拆出 `BrowserBars`、`BrowserPanels`）。函数原样搬成扩展函数，对象和 Activity 里的状态都没动。
3. **`ChatViewModel.kt` 1448 → 1107 行**：改写对话历史的那几个（重新回答、改消息、切版本、删消息、接着写）搬到 `ChatViewModelHistory.kt`，分享进来的入口搬到 `ChatViewModelShare.kt`。最核心的 `startReply`（约 430 行）先不拆，它和停止、并行、自动接着做缠在一起，拆它不算低风险。
4. 修了不稳定的 `PhotoEditorTest`（第 1 批顺手做了）。
5. 清了 3 处没用的代码（一个没用的按钮组件、两个没用的常量）。只查了「私有、本文件里再没出现」的；跨文件的没用代码要靠人判断，没动。

每一步都核对过：搬前搬后代码行一模一样（除了 import、可见性），搬出去的函数名不和留下的成员、Activity 自带的方法、同包的函数撞名（撞名可能让调用悄悄换成另一个函数），编译、全部单测通过。

## 第 3 批（风险大，先不做）

- 拆成多个 Gradle 模块（浏览器、Office、媒体各一个），编译能快很多，但要理清依赖、改构建脚本。
- 对话和设置的存储换成数据库（现在是 JSON 文件）。要做数据迁移，出错会丢聊天记录。
- `ChatViewModel` 的状态整体重写成按对话分开的状态。
- 引入依赖注入框架。
