# 工具包与工作流方案（定稿）

借鉴 Operit 的 ToolPkg 和可视化工作流，按 Kavi 已有的东西重新设计。只借思路，不抄代码（Operit 是 LGPL-3.0）。

Jack 2026-11-23 确认按推荐做：内置 QuickJS、兼容 Operit 脚本（排在后面）、卡片编辑器、后台往外的事保存时一次授权、先不做市场。

先说结论：

- **工具包**：一个文件夹或压缩包，里面放说明文件和一段 JavaScript，装上以后 Kavi 多出几个工具。Kavi 自己也能写工具包。
- **工作流**：「什么时候开始 → 一步步做什么 → 按条件分叉」，存成固定的步骤，到点或碰到条件就自己跑，不用每次问模型怎么做。手机上用**一张张卡片竖着排**来编辑（像 iPhone 的「快捷指令」），不做拖线的画布。
- 两者是一套：工作流的每一步可以调用任何工具（包括工具包里的），工具包也可以自带工作流。

---

## 一、Kavi 现在已经有的

方案要接在这些上面，不另起炉灶：

| 已有的 | 是什么 | 和这次的关系 |
|---|---|---|
| 技能 | 一段做某类活的方法（文字说明） | 工具包是「能执行的」，技能是「怎么做的说明」，两个并列 |
| 插件 | Kavi 自带的工具（Word、邮箱、浏览器……） | 工具包装上后和插件放在一起显示 |
| MCP | 连外部的工具服务器 | 工具包是装在手机里跑的，不用另开服务器 |
| 跑代码 | Rhino 跑 JS（只能算）、Python、Linux 沙箱（有 Node 22） | 工具包需要一个能联网、支持 async/await 的 JS 引擎 |
| 定时任务 | 到点提醒、到点让 Kavi 干活、监控条件满足后接着做 | 工作流是它的升级版：多步、能分叉、不必每步都问模型 |
| 手机流程 | 录下来的手机操作，能重放 | 工作流里的一种步骤 |
| 运行记录、收件箱 | 后台跑完的结果放哪 | 工作流跑完也放这里 |

## 二、工具包

### 1. 长什么样

一个工具包就是一个文件夹（分享时打成 `.zip`）：

```
kuaidi/
├── kavi-pack.json     ← 必须有：名字、工具、要什么权限
├── main.js            ← 工具的代码
├── README.md          ← 给人看的说明（可选）
└── icon.png           ← 图标（可选）
```

`kavi-pack.json`：

```json
{
  "id": "kuaidi",
  "name": "快递查询",
  "version": "1.0.0",
  "description": "按单号查快递走到哪了",
  "author": "Jack",
  "permissions": {
    "net": ["api.example-kuaidi.com"],
    "files": "pack",
    "notify": true
  },
  "config": [
    { "key": "apiKey", "label": "快递 API 的 Key", "secret": true, "required": true }
  ],
  "tools": [
    {
      "name": "track",
      "description": "查一个快递单号的物流轨迹",
      "parameters": {
        "number": { "type": "string", "description": "快递单号", "required": true },
        "company": { "type": "string", "description": "快递公司，不填自动识别" }
      }
    }
  ]
}
```

`main.js`：

```js
export async function track({ number, company }, kavi) {
  const r = await kavi.http.get("https://api.example-kuaidi.com/track", {
    query: { no: number, com: company ?? "auto" },
    headers: { Authorization: kavi.config.apiKey },
  });
  if (!r.ok) throw new Error("查不到：" + r.status);
  const data = r.json();
  return data.traces.map(t => `${t.time} ${t.text}`).join("\n");
}
```

工具的返回值交给模型看：一段文字，或者一个对象（自动转成 JSON）。抛出的错误会把原因告诉模型。

### 2. 工具包里的代码能用什么（`kavi` 对象）

只给权限里声明过的，没声明的调用直接报错：

| 能力 | 用法 | 要声明的权限 |
|---|---|---|
| 联网 | `kavi.http.get/post/request`，只能访问声明过的网站 | `net`：网站列表 |
| 文件 | `kavi.files.read/write/list`，只在工具包自己的数据文件夹里；声明了 `workspace` 才能碰当前对话的文件夹 | `files`：`pack` 或 `workspace` |
| 配置 | `kavi.config.xxx`，用户在设置里填的（Key、账号），带 `secret` 的加密存 | `config` |
| 存点东西 | `kavi.store.get/set`，小量键值，跨次保留 | 不用声明 |
| 发通知 | `kavi.notify(标题, 正文)` | `notify` |
| 调别的工具 | `kavi.tool("web_search", {...})`，只能调 Kavi 自带的只读工具 | `tools`：工具名列表 |
| 问模型 | `kavi.ai(提示词)`，用后台模型（便宜的那个），花的钱记在统计页 | `ai` |
| 手机操作 | 不开放。要操作手机，用工作流里的「手机流程」步骤，走原来的确认和拦截 | — |

跑的时候有时限（默认 30 秒，最多 5 分钟）和内存上限，超了就停。

### 3. 用什么跑

**定了：内置 QuickJS 为主，要用 npm 库的大工具包可以改用 Linux 沙箱里的 Node。** 当时比较过的三种：

| 方案 | 好处 | 代价 |
|---|---|---|
| **A. 内置 QuickJS（选这个）** | 支持 async/await 和新语法；在 App 里直接跑，几毫秒启动；不装 Linux 沙箱也能用 | 安装包大约多 1MB。候选库是 quickjs-kt（Apache-2.0）或 quickjs-wrapper（MIT），动手前再核对体积和许可证 |
| B. 用 Linux 沙箱里的 Node | 安装包不变大；npm 的库都能用 | 必须先装沙箱（58MB）；每次调用要起进程，慢半秒到一秒 |
| C. 现有的 Rhino | 不用加东西 | 不支持 async/await，联网写起来很别扭，Operit 的脚本也跑不了 |

工具包在说明文件里写 `"runtime": "node"` 时改用 B 跑；不写就用 A。

### 4. 怎么装、怎么管

- **装的来源：**
  - 选一个 `.zip` 或文件夹；
  - 从 GitHub 装（填「作者/项目」，和现在装知识库一样，记下当时的提交，更新时对比）；
  - 让 Kavi 自己写，见第 6 节。
- **装之前给你看一页确认：** 要访问哪些网站、要不要碰对话文件夹、要不要发通知、要不要花模型的钱。你点「装」才装。
- **装好以后：** 出现在技能页「插件」下面的「工具包」里，能开关、填配置、看说明、更新、删除。
- **更新：** 新版本多要了权限，就再确认一次；没多要就直接更新。

### 5. 工具怎么交给模型（照顾缓存）

工具包装多了，工具说明会很长，而且一改就让缓存全断。所以照现在 GPT 精简工具的做法：

- 平时提示词里只列「有哪些工具包、各一句话」；
- 模型用 `use_skill` 打开某个工具包，它的工具才加进来；
- 同一个对话里打开过的一直带着，免得来回变。

### 6. Kavi 自己写工具包

这是最有用的一块：你说「帮我做个查快递的工具」，Kavi 就——

1. 在对话文件夹里写出 `kavi-pack.json` 和 `main.js`；
2. 用测试工具 `test_pack` 拿真实参数跑一遍，看结果，有错自己改；
3. 跑通了交给你装（照样弹那页权限确认）。

你也可以在代码编辑器里打开它的文件自己改。

### 7. 兼容 Operit 的脚本（要做，排在后面）

Operit 有不少现成脚本（12306、B站、百度地图、学术检索……）。做一层兼容，能直接导入它的单文件脚本（开头是 `METADATA` 注释的 `.js`），只支持其中一部分：

- **能用：** `complete()`、`OkHttp`（联网）、`Tools.Net.visit`、`Tools.Files.*`（限在工具包文件夹里）、`Tools.System.sleep`。
- **不支持：** 操作界面（`Tools.UI.*`）、改系统设置这类。导入时列出它用到了哪些不支持的，让你决定还装不装。

只照着它公开的接口名做一层转换，不拷它的代码。

### 8. 安全

- 工具包的代码跑在隔离的引擎里，碰不到 Kavi 的数据、聊天记录和别的工具包。
- 返回给模型的内容按网页内容对待：先过一遍防提示词注入的检查。之后要往外做事（发邮件、发消息、存记忆）都先问你，和现在读网页之后一样。
- 从 GitHub 装的记着来源和提交；内容变了要你确认才更新。
- 一个工具包出错或超时，只影响这一次调用。

## 三、工作流

### 1. 和定时任务、手机流程的区别

| | 定时任务 | 手机流程 | 工作流 |
|---|---|---|---|
| 谁决定怎么做 | 每次都让 Kavi 想 | 重放录下的动作 | 你（或 Kavi）提前排好步骤 |
| 几步 | 一句话交给 Kavi | 只管手机操作 | 多步，什么都能串 |
| 分叉、循环 | 只有「监控满足后接着做」 | 没有 | 有 |
| 花钱 | 每次都调模型 | 不花 | 只有「让 Kavi 做」那一步花 |

定时任务和手机流程都保留。以后可以一键把定时任务「升级成工作流」。

### 2. 一个工作流长什么样

**例子：每天 8 点看三只股票，跌超 3% 就提醒我，再让 Kavi 写一句点评**

```
⏰ 什么时候开始：每个工作日 8:00
│
├─ 🔧 调用工具：股票行情（工具包）  代码 = 600519,000858,300750   → 存成「行情」
├─ 🔁 对「行情」里的每一只
│   └─ ❓ 如果  这一只.涨跌幅 < -3
│       ├─ 🤖 让 Kavi 做：「用一句话点评 {{这一只.名字}} 今天跌了 {{这一只.涨跌幅}}%」  → 存成「点评」
│       └─ 🔔 发通知：{{这一只.名字}} 跌了 {{这一只.涨跌幅}}%  {{点评}}
└─ ✅ 结束
```

### 3. 「什么时候开始」（触发）

第一批：

- **手动：** 点一下；也可以放到桌面小组件、通知栏快捷按钮。
- **定时：** 每天、工作日、每周、每隔几分钟、某个日期，用现有的定时机制。
- **监控：** 隔一段时间查一下，满足条件才往下走，就是现在「监控」的升级版。
- **在聊天里说：** 「跑一下早报工作流」，Kavi 调 `run_workflow`。

第二批：

- **收到通知：** 某个 App 的通知里出现某些字，用现有的读通知功能。
- **分享给 Kavi：** 在别的 App 里点分享，选这个工作流，分享的内容当输入。
- **打开某个 App / 连上某个 Wi-Fi / 充电时**（要看安卓给不给权限，逐个确认）。

### 4. 能放哪些步骤

| 类别 | 步骤 | 说明 |
|---|---|---|
| 做事 | 🔧 调用工具 | Kavi 的任何工具或工具包里的工具，参数可以填固定值或 `{{前面的结果}}` |
| | 🤖 让 Kavi 做 | 给一段提示词，用前面的结果当材料；可以要求它按 JSON 回，方便后面取字段 |
| | 📱 手机流程 | 重放存好的手机流程，`{关键词}` 用前面的结果填 |
| | 💻 跑代码 | Python、JS 或终端命令，输入输出走变量 |
| 往外送 | 🔔 发通知 / 💬 发到对话 / 📧 发邮件 / 📄 存成文件 | 发邮件这类往外的步骤见下面「后台跑时的确认」 |
| 逻辑 | ❓ 如果……否则 | 比大小、包含、为空、正则匹配；可以「并且」「或者」 |
| | 🔁 对每一项 | 对一个列表逐个做 |
| | ⏳ 等一会 / 等到某个条件 | |
| | ✂️ 取出 | 从文字里按正则取，从 JSON 按路径取（`行情[0].价格`） |
| | ⛔ 停下 | 提前结束，可以带一句原因 |

每一步的结果自动存成变量（默认用步骤名），后面用 `{{名字}}` 或 `{{名字.字段}}` 引用。编辑时点一下输入框，就能从前面的步骤里选，不用手打。

### 5. 编辑器：卡片竖着排，不做画布（定了）

手机屏幕小，用手指拖节点、连线很难用，Operit 那种画布在手机上也不好操作。所以：

- **卡片：** 每一步一张卡片，从上往下排；「如果」「对每一项」里面的步骤缩进显示，能折叠。
- **增删改：** 卡片之间点「＋」加一步，长按拖动换顺序，左滑删除。
- **填参数：** 卡片上直接填，变量从下拉里选。
- **试跑：** 顶上有「试跑」，每张卡片下面显示这一步实际拿到了什么，哪一步错了就标红。
- 以后可以加一个只读的「流程图」视图，方便看全貌，不在上面编辑。

**让 Kavi 帮你搭：** 你说「每天早上 8 点把我关注的三只股票行情发给我，跌超 3% 单独提醒」，Kavi 生成工作流，以卡片形式给你看，你改完点保存。

### 6. 怎么跑

- **在哪跑：** 后台跑，用现在跑定时任务的那套机制，App 被系统杀了，到点照样能起来。
- **怎么跑：** 一步一步执行，每步都有时限。整个工作流有总时限，还有花钱上限（默认一次不超过 ¥1，可以改）。
- **出错了：** 每步能设「失败了重试几次」或「失败了跳过」，默认是停下，把哪一步、为什么错了发到收件箱。
- **运行记录：** 每次跑的每一步输入、输出、用了多久、花了多少钱都记下来，在工作流页能翻。
- **结果放哪：** 跑完的结果按「发到对话 / 通知 / 收件箱」送出去。

### 7. 后台跑时的确认（定了：保存时一次授权）

没人看着的时候，往外做的事（发邮件、发消息、手机上点「发送」、删文件）这样处理：

- **保存时：** 列出这个工作流会往外做的每件事，比如「会给 xx@xx.com 发邮件」「会在微信里给『文件传输助手』发消息」，你点同意才能保存。
- **跑的时候：** 只要做的事和当时同意的一样（同一个收件人、同一个 App 里同一类操作），就不再问；超出范围的那一步停下，发通知问你。
- **撤销：** 随时在工作流页关掉授权。
- **不变的规矩：** 付款、输密码、银行页面照旧一律不碰，授权也不行。

### 8. 存成什么

一个工作流存成一个 JSON 文件，可以导出、分享，也可以放进工具包里一起发。格式大概是：

```json
{
  "id": "…",
  "name": "股票早报",
  "trigger": { "type": "schedule", "repeat": "weekdays", "time": "08:00" },
  "steps": [
    { "id": "s1", "type": "tool", "name": "行情", "tool": "stocks.quote", "args": { "codes": "600519,000858,300750" } },
    { "id": "s2", "type": "forEach", "name": "这一只", "list": "{{行情}}", "steps": [
      { "id": "s3", "type": "if", "cond": { "left": "{{这一只.涨跌幅}}", "op": "<", "right": "-3" }, "then": [
        { "id": "s4", "type": "ai", "name": "点评", "prompt": "用一句话点评 {{这一只.名字}} 今天跌了 {{这一只.涨跌幅}}%" },
        { "id": "s5", "type": "notify", "title": "{{这一只.名字}} 跌了 {{这一只.涨跌幅}}%", "body": "{{点评}}" }
      ] }
    ] }
  ],
  "limits": { "timeoutMin": 10, "maxCostYuan": 1 },
  "grants": [ ]
}
```

步骤是树形的（「如果」「对每一项」里面套步骤），不是 Operit 那种节点加连线：和卡片编辑器一一对应，也更好让模型生成、让人看懂。

## 四、分几步做

| 步骤 | 内容 | 大概多久 |
|---|---|---|
| 1. 工具包基础 | JS 引擎、说明文件、`kavi.*` 接口（联网、文件、配置、存储、通知）、权限确认页、从文件或 GitHub 安装、技能页管理 | 4～5 天 |
| 2. Kavi 写工具包 | `test_pack` 试跑、生成后交给你装；交给模型时照顾缓存 | 1～2 天 |
| 3. Operit 兼容 | 导入它的单文件脚本，常用接口转换 | 1～2 天 |
| 4. 工作流引擎 | JSON 格式、执行器、变量、「如果」和「对每一项」、手动和定时触发、运行记录、花钱上限 | 3～4 天 |
| 5. 卡片编辑器 | 增删改、拖动排序、变量选择、试跑、Kavi 生成工作流 | 3～4 天 |
| 6. 更多触发和授权 | 监控、通知、分享触发；保存时授权；定时任务升级成工作流 | 2～3 天 |

**进度：** 第 1 步做完了（2026-11-24）。

- **JS 引擎：** 用的是 quickjs-kt 1.0.0-alpha13（Apache-2.0），arm64 多大约 0.85MB。之后的版本要求 Kotlin 2.3，项目还是 2.0，所以先停在这一版，以后升 Kotlin 时一起升。
- **这版引擎的两个坑：**
  - 直接按模块执行会出错，所以 main.js 改成用动态 `import()` 加载。
  - 原生库在全局只记一份 Java 虚拟机，任何一个引擎关掉都会把它清掉，所以同一时间只开一个引擎，工具按顺序跑。
  - 另外它没有中断的口子：代码要是卡在死循环里，引擎会一直占着，直到重开 App，后面的调用会说明原因。
- **代码在哪：**
  - `data/packs/`：说明文件、引擎、安装、`kavi.*` 的权限检查；
  - `tools/PackTools.kt`：交给模型调用；
  - `ui/PacksUi.kt`：技能页上的卡片、权限确认页、详情页（填配置、试一下、检查更新、删除）；
  - 示例工具包「天气」在 `assets/packs/weather/`。
- **交给模型：** 工具包的工具和连接器一样，一直带着，排在工具列表的最后。

第 2 步做完了（2026-11-24）。

- **不做按需打开（改了主意）：** 代码里有以前实测的记录：对话中途用 use_skill 加工具，DeepSeek 的缓存从开头附近就断了，同一个对话命中率掉到 4%。所以 ON_DEMAND 早就清空了，工具包也不走这条路。工具包的工具一直带着、排在最后，只在装、删、开关的时候变一次。
- **Kavi 写工具包：**
  - 插件「做工具包」：做法写在插件说明里，第一次调它的工具时自动附上。
  - `test_pack`：先检查说明文件，再真的跑一次，返回结果、日志和用时。试跑的数据放在单独的文件夹里。
  - `install_pack`：弹出和用户自己装时同一页的权限确认页，还能看代码；App 在后台时退回普通确认框。完全授权也不会跳过这一步。
